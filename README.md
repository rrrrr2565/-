# MyLauncher — свой лаунчер Minecraft

Простой десктопный лаунчер Minecraft на Python (CustomTkinter) в тёмном стиле:
тёмно-фиолетовый интерфейс и большая зелёная кнопка **ИГРАТЬ**.

## Возможности

- Список версий с официальных серверов Mojang: **релизы** и **снапшоты** —
  новые версии Minecraft появляются в списке **автоматически** (кнопка
  «ОБНОВИТЬ СПИСОК» перечитывает сервер Mojang; при выходе новой версии
  лаунчер сообщит об этом в консоли)
- Версии **Fabric** и **Forge** (устанавливаются в один клик вместе с игрой)
- Автоматическое скачивание и установка выбранной версии с прогресс-баром
- Оффлайн-запуск по нику (без аккаунта Microsoft)
- **Полный каталог модов Modrinth**: живой поиск по тысячам модов, пагинация
  «ПОКАЗАТЬ ЕЩЁ», **обязательные зависимости скачиваются автоматически**
- **Обновления по воздуху (OTA)** — лаунчер сам проверяет этот репозиторий и обновляется
- Улучшенная консоль: метки времени, **цветные сообщения по типу события**
  (ошибки — красные, предупреждения — жёлтые, моды — фиолетовые, запуск — зелёные),
  фильтр сообщений, кнопки «Сохранить лог» и «Очистить», автозапись в `launcher.log`
- Кнопка «Завершить игру» — принудительно закрывает процесс Minecraft
- Установка также чинит повреждённые файлы уже установленной версии

## Что нового в 1.4.1

- **Исправлен exe-запуск**: раньше при запуске MyLauncher.exe папка `.minecraft`
  и логи попадали во временную папку `_MEI…` и исчезали после закрытия —
  теперь игра и все файлы живут рядом с exe
- **Авто-загрузка Java**: если системной Java нет (ошибка «WinError 2») или она
  слишком старая, лаунчер сам скачивает официальный рантайм Mojang нужной
  версии (Java 8/17/21/25 — по выбранной версии Minecraft) в `.minecraft/runtime`
- **Старые версии модов удаляются автоматически**: при скачивании Fabric API
  новой версии старый jar убирается из `mods`, чтобы моды не конфликтовали
- **Порядок в папке**: служебные файлы (логи, маркеры, бэкапы) теперь
  складываются в подпапку `launcher_data`, а не в корень рядом с exe
- **Нормальная сортировка**: версии Fabric — по новизне MC, версии Forge —
  сначала новая версия Minecraft, затем свежий билд

## Каталог модов

Кнопка **«КАТАЛОГ МОДОВ (MODRINTH)»** открывает окно с живым поиском по всему
Modrinth — это более 14 000 модов для Fabric и тысячи для Forge.

Как пользоваться:

1. Сначала выберите тип версии **Fabric** или **Forge** и версию Minecraft —
   каталог работает только для модовых загрузчиков.
2. Откройте каталог: сразу показаны самые популярные моды под вашу версию.
3. Введите запрос в строку поиска (например `sodium`, `JEI`, `create`) и нажмите **НАЙТИ**.
4. Отметьте галочками нужные моды (клик по строке тоже переключает галочку).
5. Нажмите **СКАЧАТЬ ВЫБРАННЫЕ** — лаунчер:
   - подбирает последнюю версию каждого мода строго под вашу связку MC + загрузчик;
   - **сам находит и скачивает обязательные зависимости** (например, для
     Sodium Extra автоматически скачается Sodium) — вся цепочка, без циклов и дубликатов;
   - **автоматически удаляет из mods старые версии этого же мода**
     (например, поставили Fabric API посвежее — старый jar уберётся сам);
   - уже скачанные файлы не перекачивает;
   - если модов именно под вашу версию MC нет, показывает весь каталог
     загрузчика с предупреждением.

Файлы кладутся в `.minecraft/mods` и появятся в игре после следующего запуска
Minecraft через лаунчер. Мод без версии под вашу связку пропускается с пометкой
в консоли.

## Требования

- **Python 3.9+** (проверено на 3.12) — [python.org](https://www.python.org/downloads/)
  при установке на Windows отметьте галочку *Add Python to PATH*
- **Java** — нужна не всегда: лаунчер сам разберётся. Если системной Java нет
  или она слишком старая, он скачает официальный рантайм Mojang нужной версии
  (сохраняется в `.minecraft/runtime`). Свою Java можно указать в поле
  «Путь к Java» — [adoptium.net](https://adoptium.net/)

## Быстрый старт (Windows)

1. Скачайте файлы репозитория (кнопка **Code → Download ZIP**), распакуйте
2. Запустите `run.bat` — двойной клик. Он сам установит зависимости и откроет лаунчер.
3. Хотите настоящий exe? Запустите `build_exe.bat` — он соберёт `dist\MyLauncher.exe`.
   После сборки exe можно запускать двойным кликом, Python больше не нужен.

## Установка вручную (Windows / macOS / Linux)

```bash
pip install -r requirements.txt
python launcher.py
```

## Как пользоваться

1. Выберите тип версии: **Релизы** (стабильные), **Снапшоты** (тестовые),
   **Fabric** или **Forge** (моды).
2. Выберите версию в выпадающем списке (первая в списке — самая свежая).
3. Введите ник (если поле пустое, будет использован `Steve`).
4. Нажмите **ИГРАТЬ**. Лаунчер скачает файлы (в первый раз это несколько сотен
   МБ, следите за прогресс-баром) и запустит игру.
5. Лог установки и игры виден в правой панели «КОНСОЛЬ»: каждая строка с
   меткой времени и своим цветом (ошибки — красные, предупреждения — жёлтые,
   моды — фиолетовые, запуск и установка — зелёные). Выпадающий список над
   консолью фильтрует сообщения по типу, кнопки внизу сохраняют лог в
   `launcher_log.txt` и очищают окно. Весь лог также автоматически пишется
   в файл `launcher_data/launcher.log` (при размере свыше 5 МБ
   переименовывается в `launcher.log.old`).

## Где лежат файлы игры

По умолчанию игра устанавливается в папку `.minecraft` рядом с лаунчером
(для exe — рядом с самим exe).

Чтобы использовать другую папку (например, уже имеющийся `.minecraft`),
создайте файл `launcher_data/launcher_dir.txt` и впишите в него
полный путь, например:

```
C:\Users\Иван\AppData\Roaming\.minecraft
```

## Путь к Java

Обычно ничего указывать не нужно: лаунчер сам разберётся. Если системная Java
подходит — используется она; если Java нет или она слишком старая для выбранной
версии Minecraft — лаунчер скачает официальный рантайм Mojang (один раз,
сохраняется в `.minecraft/runtime`). Указать свой путь можно в поле «Путь к Java»
(например `C:\Program Files\Eclipse Adoptium\jdk-21\bin\javaw.exe`)
или нажать **Найти** — лаунчер поищет Java в PATH.

## Обновления по воздуху (OTA)

Лаунчер умеет обновлять сам себя — без повторного скачивания игры.
При каждом запуске (через 2.5 секунды) он молча проверяет канал обновлений
на GitHub, а кнопка **«ПРОВЕРИТЬ ОБНОВЛЕНИЯ»** запускает проверку вручную.

**Вариант 1 — GitHub-репозиторий (основной, работает из коробки):**

Канал обновлений зашит в код: `https://raw.githubusercontent.com/rrrrr2565/-/main/version.json`.
Чтобы выпустить новую версию, достаточно отредактировать два файла в репозитории:

1. Залить обновлённые файлы программы (`launcher.py`, README, bat-файлы и т.д.)
2. В `version.json` поднять номер и перечислить обновляемые файлы:
   ```json
   {
     "version": "1.4.1",
     "files": {
       "launcher.py": "https://raw.githubusercontent.com/rrrrr2565/-/main/launcher.py",
       "README.md": "https://raw.githubusercontent.com/rrrrr2565/-/main/README.md"
     }
   }
   ```
3. У всех пользователей при следующем запуске появится окно
   «Доступна версия 1.4.1 — УСТАНОВИТЬ / ПОЗЖЕ». После установки лаунчер
   предложит **«ПЕРЕЗАПУСТИТЬ ЛАУНЧЕР»** — и запустится уже новой версией.

Манифест поддерживает и второй формат — ссылкой на zip-архив:
`{"version": "1.4.1", "files_url": "https://example.com/MyLauncher-update.zip"}`.

**Вариант 2 — локальный файл обновления (без интернета):**
1. Получите новый `MyLauncher-update.zip`
2. Положите его в папку `launcher_data` рядом с `launcher.py` — лаунчер сам заметит его при запуске
3. Нажмите **«УСТАНОВИТЬ»**, затем **«ПЕРЕЗАПУСТИТЬ ЛАУНЧЕР»**

Во всех вариантах обновляются только файлы программы. Папка `.minecraft`
со всеми скачанными версиями, библиотеками и модами **не трогается**.
Старый launcher.py сохраняется как `launcher_data/launcher.py.bak`,
а применённый zip переименовывается в `.applied`, чтобы обновление
не предлагалось по кругу. Ссылку на свой канал обновлений можно вписать в файл
`launcher_data/update_url.txt` — тогда код менять не нужно. Учтите: raw.githubusercontent.com
кэширует файлы на ~5 минут, поэтому новое обновление может появиться с небольшой задержкой.

**Важно для exe:** сборка `MyLauncher.exe` не умеет обновлять сам бинарник —
после OTA-обновления launcher.py пересоберите exe через `build_exe.bat`.

## Решение проблем

| Проблема | Решение |
| --- | --- |
| `Не найден customtkinter` | `pip install -r requirements.txt` |
| Ошибка скачивания версий | Проверьте интернет; список берётся с `launchermeta.mojang.com`, моды — с `api.modrinth.com` |
| `WinError 2` при установке | Не найдена Java — теперь лаунчер сам скачает рантайм Mojang; либо установите Java с adoptium.net и нажмите «Найти» |
| Forge не устанавливается | Старые версии Forge не поддерживают автоустановку — возьмите версию посвежее |
| Моды пропускаются | У мода нет версии под вашу связку MC + загрузчик; смотрите пометки в консоли |
| Древние версии (1.0–1.5) не работают | Это ограничение самих версий: сервер ресурсов Mojang отключён (нет звука), нужна Java 8, они могут завершаться сразу. Лаунчер предупредит и создаст недостающие иконки, но надёжнее играть на 1.20.1+ |
| Игра сразу закрывается | Посмотрите последнюю строку в «КОНСОЛИ» — чаще всего не хватает Java нужной версии |
| Антивирус ругается | Лаунчер запускает официальный Minecraft через `java`, добавьте папку в исключения |
| Обновление не находится | Проверьте интернет; если используете свой канал — проверьте ссылку в `launcher_data/update_url.txt`. Локальный zip должен называться точно `MyLauncher-update.zip` и лежать в `launcher_data` |

## Структура проекта

```
├── launcher.py        # весь код лаунчера (один файл)
├── requirements.txt   # зависимости
├── run.bat            # быстрый запуск на Windows (двойной клик)
├── build_exe.bat      # сборка MyLauncher.exe на Windows (двойной клик)
├── version.json       # манифест OTA-обновлений (не редактировать без нужды)
├── launcher_data/     # служебные файлы (логи, бэкапы, маркеры) — создаются сами
│   ├── update_url.txt         # необязательно: своя ссылка на сервер обновлений
│   └── MyLauncher-update.zip  # необязательно: локальный файл обновления
└── .minecraft/        # создаётся автоматически при первом запуске
```
